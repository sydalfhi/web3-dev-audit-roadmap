Detail tiap fase

Fase 1: ERC-721 dan standar token lain

Minggu 1-2
  • ERC-721: ownerOf, approve, setApprovalForAll, safeTransferFrom
  • Metadata dan tokenURI (IPFS / on-chain)
  • ERC-1155 untuk multi-token
  • ERC-2981 royalti, ERC-4626 vault (kenalan saja)
  • Pahami callback onERC721Received dan risiko reentrancy-nya
  • Baca source OpenZeppelin, jangan cuma import

Hasil: kontrak NFT mint + whitelist (Merkle) dengan test Hardhat.

Fase 2: Pindah ke Foundry

Minggu 3-5
  • Install, forge init, struktur src / test / script
  • Test dalam Solidity: assert, expectRevert, expectEmit
  • Cheatcodes: vm.prank, vm.deal, vm.warp, vm.roll
  • Fuzz test dan invariant test
  • Fork mainnet (vm.createSelectFork) dan anvil
  • forge script untuk deploy, cast untuk interaksi

Hasil: porting kontrak ERC-20 dan ERC-721 lama kamu dari Hardhat ke Foundry, lengkap dengan fuzz test. Hardhat tetap boleh dipakai untuk deploy.

Fase 3: dApp / Frontend (jalur tercepat dapat kerja)

Minggu 5-8
  • Ulang ethers.js v6: Provider, Signer, Contract, event listener
  • Kenalan viem + wagmi (standar baru di industri)
  • Next.js + RainbowKit / WalletConnect
  • Handle error: reject, salah network, gas, tx pending
  • Baca data on-chain: multicall, The Graph / indexer
  • Deploy ke testnet (Sepolia) dan Vercel

Hasil: dApp NFT mint dan staking sederhana yang live di testnet, repo rapi dengan README.

Fase 4: Pola kontrak yang sering dipakai

Minggu 8-12
  • Proxy / upgradeable (UUPS, Transparent), storage layout
  • Access control, pausable, timelock, multisig
  • AMM sederhana ala Uniswap v2
  • Staking dan reward distribution
  • Lending dasar (Compound / Aave sebagai bahan baca)
  • Oracle: Chainlink, TWAP, dan risikonya

Hasil: mini-AMM atau staking dengan test lengkap, ditulis ulang dari nol tanpa copy-paste.

Fase 5: Keamanan dan audit

Minggu 10-16
  • Kerentanan: reentrancy, access control, precision, oracle manipulation, front-running, flash loan
  • Selesaikan Ethernaut
  • Damn Vulnerable DeFi (pakai Foundry)
  • Tools: Slither, Echidna, Foundry invariant
  • Baca 2-3 laporan audit publik per minggu (Code4rena, Sherlock)
  • Coba AI untuk bantu cari bug, lalu verifikasi sendiri dengan PoC

Hasil: catatan temuan pribadi dan beberapa PoC exploit di GitHub.

Fase 6: Portofolio, kontes, dan kerja

Minggu 14 dan seterusnya
  • Hackathon online (ETHGlobal, Devfolio), menang atau tidak tetap jadi portofolio
  • Kontes audit: Code4rena, Sherlock, Cantina (mulai dari kontes kecil)
  • Lamar posisi dApp / Frontend / Smart Contract Dev junior
  • GitHub rapi: README, test, deploy address
  • Aktif di Twitter/X dan Discord komunitas Web3
  • Manfaatkan bahasa Inggris, kerja remote lintas negara

Hasil: 1 kontes audit selesai, 2-3 dApp live, dan lamaran pertama terkirim.

Aturan main

  • Satu sesi AI, cek tiap file yang dibuat. Kebiasaan ini sudah skill auditor.
  • Tulis kontrak inti sendiri dulu, baru minta AI review. Bukan sebaliknya.
  • Tool baru (opencode, dsb.) cukup dicoba 20% waktu, jangan jadi tujuan.
  • Mulai kontes sebelum merasa siap. Hasil awal kosong itu normal.

Target realistis

  • Bulan 1: standar token selesai, Foundry jalan.
  • Bulan 2: dApp pertama live di testnet.
  • Bulan 3-4: pola DeFi dan kerentanan dasar.
  • Bulan 4-5: kontes audit pertama dan lamaran kerja.
Jalur utama: dApp dev dulu, audit sebagai pembeda. Satu jalur, saling menguatkan.
